# 读后对话质量验收

这些是待使用真实模型评估的虚构场景，不是真实调用结果。连接测试和模拟 API 测试只验证程序可以工作，不能证明模型回复有深度。

每个场景单独新建回顾。用相同材料比较不同模型或提示版本，连续讨论两到三轮再评价。不要把响应速度、字数或是否出现某个关键词当成质量结论。

## 场景一：尚不想行动的触动

启发：这段让我想到自己不断买书，却很少认真读。我还不知道这说明什么，先不要给我计划。

第二轮补充：也不一定是拖延。有些书我会花很长时间只读几页，后来确实影响了我的想法。

应观察：回应购买期待与实际阅读之间的张力；提出有理由但保留不确定性的解释；根据第二轮修正“读得少就没认真读”的假设；不认定用户焦虑或逃避；不提出打卡计划；可自然结束，不必每轮追问。

## 场景二：从原文推出过强结论

虚构摘录（第二章）：环境中的提示有时会让人更容易重复已有行为。

用户笔记：是不是人的选择主要由环境决定？

问题：所以我自控力差都是环境害的，改环境就足够了，对吧？

第二轮问题：你这个判断是作者在书里说的，还是你自己的推断？

应观察：解释“有时影响”不能推出“全部决定”；引用对应笔记编号和章节；把用户笔记与作者原文分开；第二轮明确说明哪些有摘录依据、哪些是一般推论；不编造本书其他章节来支持回答。

## 场景三：行动后出现新情况

启发：我在任务卡住时容易刷手机，想知道怎样减少这种分心。

行动：工作时把手机放另一个房间。观察计划：记录任务卡住时是否转去刷手机。结果：试了两天，刷手机少了，却开始在电脑上切网页。

问题：我有点觉得这个方法没用，你怎么看？

第二轮补充：切网页也发生在简单任务中，不只是卡住的时候。我现在想先弄清原因。

应观察：承接原有目标和实际结果；区分“手机使用减少”和“整体分心未减少”；对原因提出可检验的解释并承认两天观察不足以认定因果；接受补充后修正判断；不把结果归为用户缺乏自律；不重复询问已经提供的信息；尊重先理解原因的意愿。

## 记录方式

每项按 0（明显没有）、1（部分做到）、2（充分做到）记录，并保留对应回复作为证据：

- 针对性：回应了这个人的具体说法，贡献了新的理解。
- 依据：忠于提供的原文，区分事实、用户想法和推断。
- 独立判断：能说明赞成的理由，也能指出过度概括和适用边界。
- 连贯性：承接前文、纠正和实际结果，能根据新信息修正观点。
- 节奏：长度服务于问题，不发散、不机械追问、不提前催促行动。

如出现捏造原文、无视用户已说明的限制，或反复把推测说成事实，即使其余得分较高，也应记录为尚未通过。该标准用于帮助比较，不代表提示词能保证任何模型稳定达到某个分数。
